# Chase Director

Import the chase scene in Adventure Manager, open Chase Director and initialize overlays before activating the scene for players. The eight panel positions are measured against the existing 2172 × 724 unbranded board; verify the slanted card covers and labels in Foundry v14. The original card cover is layered over a matching opaque mask. Covers are a theatrical reveal effect only: obstacle art and names are already in the background file, and chase state is visible scene data. Do not use it for confidential encounter preparation.

Enter the required chase points per obstacle from your own adventure or custom rules. No defaults from the published adventure are bundled. Blank requirements are unset. Save requirements before other actions. Use +1, +2, and −1 to update points on any obstacle; a reached target is highlighted but never moves participants automatically. Move Party and Drone independently; Party arrival reveals an obstacle, Drone arrival does not. Next/previous round changes only the round counter. Backtracking retains earned points so corrections are possible. Reaching the hideout is tracked but does not automatically resolve the encounter. Cover/reveal any obstacle, reveal all, or toggle covers. Clear progress only after checking confirmation; requirements survive reset. All progress is stored in the scene flag, and overlays are tagged native Tiles and Drawings. No actor, combat tracker, automatic rolls, or player navigation is changed.

Initialize / repair rebuilds or reconciles managed objects from stored state, preserving unrelated scene objects. State is saved first; retry repair if an overlay operation fails. Use one GM client, and save requirements before switching controls. Artwork and native rendering, drawing text, layer ordering and player synchronization still require live Forge testing. No adventure DCs, obstacle rules, or outcomes are included.

Macro: `await game.modules.get("gg-murder-in-metal-city").api.openChaseDirector();`
