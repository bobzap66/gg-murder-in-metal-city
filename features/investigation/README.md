# Investigation artwork and card templates

This is a reusable, unbranded art and template layer, not yet an integrated Foundry feature. `catalog.json` describes the 1672 × 941 investigation board, its eleven evidence slots, its replaceable subject portrait and nameplate, and twelve evidence card types. Position values are normalized fractions of the background image, with top-left origin. Each slot can hold any one card; twelve template types are available, so the GM can choose, reuse, or rotate them. Coordinates are initial visual measurements; verify alignment inside Foundry.

`card.mjs` exports `renderEvidenceCard(template, values, options)`, which returns a DOM element. Load `card.css` wherever the renderer is used. Values are keyed by the field IDs in the selected template and displayed as literal text (not HTML). Missing values are blank placeholders. The default asset path is module-relative; an alternate base can be provided for a standalone preview. Use the full card in a journal/viewer and the illustration or short label on the board; do not shrink long evidence text into small tile slots.

The renderer does not read journals, persist evidence, implement ownership, or reveal documents. A later integration must enforce GM authority, use only player-authorized and revealed fields, and keep secret GM notes separate. Do not include published adventure handouts, clues, or player-specific campaign data in the module. GMs provide their own information and any licensed subject portrait.

The images are newly AI-generated, unbranded generic illustrations, with no adventure-specific clue data. Some images contain incidental fictional screen glyphs or timestamps as decorative details, not as evidence. The twelve thumbnails were cropped from a contact sheet; they are intended as small card illustrations rather than full-screen art.

## Shared evidence library and board integration

Open Shared evidence library in Adventure Manager. Save a private draft with a title, template, optional custom artwork, player-facing findings and separate GM-only notes. Publish saved draft explicitly to create a player-readable native JournalEntry snapshot in Discovered Evidence. Draft revisions do not affect that snapshot. To update published information, withdraw first, then publish again. Withdrawal revokes the default permission and removes module-tagged Tile and Note placements before deleting the snapshot; it does not erase player memories, downloads, manually shared copies or external links. Use native ownership settings responsibly and do not share the private draft folder. No private fields are copied into public journal snapshots or scene flags. Foundry permissions are not encryption; test with an actual player account before using spoilers.

The board supports eleven independently replaceable slots, with aspect-fit illustrations and native journal pins. Players can also browse the discovered journals normally. Enable map notes on the client if pins are not visible. Only published records that all non-GM users can read are available. A case subject portrait and name can be placed or cleared independently. Subject fields are public immediately when applied. A board slot replacement clears only module-tagged tiles and notes in that position. Do not use hidden scene objects for secret evidence.

The editor is authoritative for private draft fields; save before switching records, selecting a board, or taking another action. Repeated edits do not republish automatically. Use a single GM client to avoid races. If an operation fails partway, refresh and retry; unpublished incomplete snapshots can be withdrawn. No automatic player navigation or journal popups occur. Custom art paths must already exist in Foundry or be valid image URLs. The renderer helper remains available for future custom exhibit views. The library exposes availableEvidence() for the future courtroom exhibit controller. No published adventure data is bundled.

Macro: `await game.modules.get("gg-murder-in-metal-city").api.openEvidenceManager();`
